6. Debugging & Root Cause Analysis (RCA)

The following critical issues were identified during inspection and successfully debugged and resolved:

🐛 Issue 1: Missing User Relationship in Candidate Creation (HTTP 409 / 500)

Root Cause: In CandidateServiceImpl.createCandidate, the Candidate entity was constructed via CandidateMapper.toEntity(request), but the candidate.setUser(user) mapping was never set. Because user_id on table candidates has a database NOT NULL constraint, PostgreSQL rejected the transaction with a constraint violation.

Resolution: Modified CandidateServiceImpl.java to look up the User entity by request.getUserId() and associate candidate.setUser(user) prior to saving.

🐛 Issue 2: Role-Based Authorization Returned 401 Instead of 403 Forbidden

Root Cause: When an authenticated candidate attempted to access recruiter-only endpoints (e.g. POST /recruiter/profile, POST /jobs), Spring Security denied access and forwarded to /error. Because /error was not configured in permitAll() and no AccessDeniedHandler was registered, Spring Security re-evaluated the error forward as an unauthenticated request and returned a misleading 401 Unauthorized.

Resolution: Implemented JwtAccessDeniedHandler.java to return structured JSON with HTTP 403 Forbidden, and added .accessDeniedHandler(jwtAccessDeniedHandler) and /error to permitAll() in SecurityConfig.java.

🐛 Issue 3: Malformed JWT Caused Unhandled 500 Server Error

Root Cause: Passing an invalid, expired, or malformed JWT token caused io.jsonwebtoken parser to throw an unhandled runtime exception inside JwtAuthenticationFilter.java, which bypassed Spring MVC exception handlers and bubbled up as an HTTP 500 error.

Resolution: Wrapped JWT parsing and claim extraction in a try-catch block inside JwtAuthenticationFilter.java. On parser exception, the security context is cleanly cleared, allowing Spring Security's JwtAuthenticationEntryPoint to return HTTP 401 Unauthorized.
